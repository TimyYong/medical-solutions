| 板块 | 性质 | 文档数 |
| --- | --- | --- |
| 嘉和文件 | 医院核心业务、临床大数据、专病库，含大量医院售前投标与实施文档 | 2978 |
| 翼康文件 | 公共卫生、区域卫生平台、区县卫健委、疾控课题 | 4898 |
| 奇点文件 | 医学大数据、科研平台、全民健康平台、疾控 | 1625 |
| 306文件 | 306 医院在办项目（需求、周报、方案） | 33 |
| 医联文件 | 互联网医疗 / AI 医生方向 | 10 |
| 友邦 | 非主业（保险/个人资料），独立隔离 | 13 |

## 快速上手

```bash
cd "D:/WORKBUDDY 2/2026-11-16-12-09-44/医疗信息化资料库/04-工具"

python search.py "互联互通 成熟度"        # 全文检索
python search.py "电子病历" --type 招投标  # 按类型过滤
python search.py "专病库" --vendor 奇点文件  # 按厂商过滤
python search.py --stats                  # 库统计
python search.py --projects 天坛           # 项目清单
```

结果给出 `文件名 / 路径 / 厂商 / 类型 / 业务域 / 大小 / 日期 / 正文片段`，按路径可直接打开原件。

**排序规则**：先取 300 条候选，按类型限额（周报类≤3）过滤，再按「FTS 位次 × 文档类型权重 × 文件名命中」重排，同文档多版本折叠为「另有 N 个版本」。所以方案、标书、政策会排在过程记录前面。

## 分类口径

- **文档类型**（按文件名关键词判定）：招投标、合同协议、实施验收、方案设计、商务报价、需求调研、汇报材料、过程管理、政策标准、资质证照、科研数据、培训手册、数据报表
- **业务域**：电子病历与评级、互联互通、HIS 与核心业务、LIS 与检验、PACS 与影像、DRG\_DIP 与医保、绩效考核与运营、科研与专病库、公共卫生与疾控、集成平台与接口、基础设施与安全、项目管理与商务
- **索引分层**：A 层知识型文档全文入库；B 层原始数据仅登记元数据；C 层大文件（\>30MB）、压缩包、图片、视频只入册不解析

## 已知局限

1. **扫描件 OCR 已覆盖高价值部分**：925 份图片型文档（合同、盖章标书、证书、中标通知书）已 OCR 补录 **192 份 / 58.7 万字**，正文按 `[第N页]` 分段便于核对页码。仍有 733 份无正文，其中一半是发票、订单、签到表等票据类，检索价值低。细节见 `00-索引/OCR补录报告.md`。
2. **表格图片只能取到零散数字**：报价单、参数对比表这类纯表格扫描页，OCR 会丢失行列结构。
3. **老格式 **`.doc/.xls`：为二进制格式，正文靠启发式抽取，质量低于 docx/xlsx；另有 29 个改了后缀的假 `.docx`（实为 Word 97 二进制），无法解析。
4. **压缩包只到文件名级**：320 个压缩包（zip 163 / rar 155 / 7z 2，共 5826 个内部文件）已把**包内文件名**纳入索引，可直接搜到「哪个包里有什么」；但包内正文未解压未提取，需按需解压后补录。
5. **分类基于文件名**：文件名过于笼统（如 `1.docx`、`汇报).pptx`）会落入「其他」，需结合全文检索使用。
